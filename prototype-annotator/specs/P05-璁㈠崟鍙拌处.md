## 02 页面业务说明

### 页面目标

按分配订单查看客户码量、已激活量、绑定申请占用量和剩余可用量。

### 业务场景

码段分配后形成订单，后续产品绑定、激活、撤回和剩余可用量均以订单及其连续码段为基础。

- 按客户、订单号和分配日期筛选
- 按各码量字段排序
- 查看绑定申请中明细
- 进入订单详情

### 业务对象

## 05 业务规则

### 数据校验规则

- 直接绑定须再次校验连续可用范围

### 计算规则

- 剩余可用 = 订单码量 - 已激活 - 绑定申请中，最小为 0
- 订单剩余量为 0 时禁用继续绑定

### 操作规则

- 未选择其他排序条件时，列表默认按分配时间倒序排列，最新记录在前；用户主动选择排序后按所选规则执行。
- 按客户、订单号和分配日期筛选
- 按各码量字段排序
- 查看绑定申请中明细
- 进入订单详情
- 直接绑定客户已有已激活产品
- 导出台账
- 已撤销分配的订单不在有效台账展示
- 订单号和码段按字符串处理
- 无绑定申请时绑定申请中为 0
- 筛选、排序和分页状态应保持一致

### 数据一致性规则

- 四项码量同排展示且计算一致
- 点击记录能进入对应订单而非错误示例
- 导出结果遵循当前筛选条件
- 页面数据以后端当前有效业务关系为准，关联页面使用同一数据口径。

## 06 状态管理

### 状态定义

| 状态 | 定义 |
| --- | --- |
| 有效 | 订单码段可用于绑定 |
| 部分占用 | 存在激活或待审批绑定 |
| 无剩余 | 全部码量已占用 |
| 已撤销 | 整笔分配已撤销 |

### 状态转换图

```mermaid
stateDiagram-v2
  state "有效" as valid
  state "部分占用" as occupied
  state "无剩余" as exhausted
  state "已撤销" as recalled
  [*] --> valid: 分配成功
  valid --> occupied: 提交绑定或激活
  occupied --> exhausted: 剩余量归零
  occupied --> valid: 驳回或撤回占用
  valid --> recalled: 撤销分配
```

### 转换条件

| 当前状态 | 目标状态 | 转换条件 |
| --- | --- | --- |
| 初始 | 有效 | 分配成功 |
| 有效 | 部分占用 | 提交绑定或激活 |
| 部分占用 | 无剩余 | 剩余量归零 |
| 部分占用 | 有效 | 驳回或撤回占用 |
| 有效 | 已撤销 | 撤销分配 |

### 禁止转换

- 状态转换图中未定义的转换一律禁止。
- 前端不得直接指定目标状态，后端必须根据当前状态和业务条件执行转换。
- 后续业务过程不得覆盖历史审核或操作状态。

- 仅启用状态的运营人员可访问。

## 09 异常与边界

### 重复操作

- 写操作必须携带客户端请求标识并保证幂等；重复提交不得重复创建记录、扣减数量或发送通知。

### 并发处理

- 后端在提交时重新校验记录版本、当前状态及数量；发生冲突时拒绝本次操作并返回最新数据。

### 超时处理

- 请求超时时保留当前查询或表单上下文，不得预先写入成功状态；重试时沿用原幂等标识。

### 数据异常

- 查询成功但无记录时展示明确空状态，保留可用的新增、返回或重试入口。
- 未登录、账号禁用、越权访问或数据不属于当前主体时终止操作，并返回无权限或安全的空结果。
