## 02 页面业务说明

### 页面目标

接收并查看与本人产品绑定和撤回审核相关的结果通知。

### 业务场景

系统通过站内信传递绑定和撤回审核结果，消息范围必须与当前登录主体严格隔离。

- 首行仅展示消息标题、内容摘要、重置和高级筛选
- 高级筛选展开后显示接收时间、消息类型和阅读状态
- 打开消息详情
- 批量标记已读
- 批量删除
- 站内信均由业务状态变更自动生成，不提供人工新建、编辑或手动补发入口
- 标记已读和全部标为已读两个按钮固定在高级筛选右侧

### 业务对象

| 业务对象 | 页面内职责 | 数据来源与落地要求 |
| --- | --- | --- |
| 当前客户会话 | 页面初始化、关联查询或状态计算 | 当前原型为 localStorage / 页面上下文；正式接口待后端契约确认 |
| 站内信 | 页面初始化、关联查询或状态计算 | 当前原型为 localStorage / 页面上下文；正式接口待后端契约确认 |

## 05 业务规则

### 操作规则

- 列表默认按接收时间倒序排列，最新记录在前。
- 按标题、内容快速筛选，高级筛选后按接收时间、消息类型和阅读状态筛选
- 批量删除
- 打开消息详情
- 批量标记已读
- 本页只展示系统自动生成的业务结果类站内信，不展示业务提交过程中的内部流转提示
- 只展示当前客户的业务结果消息
- 分配码段不产生站内信
- 申请提交类内部动态不作为站内信
- 删除消息不影响业务记录
- 未读、已读
- 无消息时显示空状态
- 批量操作未选择记录时不可执行

### 数据一致性规则

- 不会看到其他客户消息
- 打开未读消息后更新阅读状态
- 通知内容可对应到真实业务记录
- 标题和内容摘要列应适当加宽，接收时间和消息类型列相对收窄
- 页面数据以后端当前有效业务关系为准，关联页面使用同一数据口径。

## 06 状态管理

### 状态定义

| 状态 | 定义 |
| --- | --- |
| 未读 | 接收方尚未打开 |
| 已读 | 接收方已查看 |
| 已删除 | 消息不再在列表展示 |

### 状态转换图

```mermaid
stateDiagram-v2
  state "未读" as unread
  state "已读" as read
  state "已删除" as deleted
  [*] --> unread: 发送消息
  unread --> read: 打开或标记已读
  unread --> deleted: 删除
  read --> deleted: 删除
```

### 转换条件

| 当前状态 | 目标状态 | 转换条件 |
| --- | --- | --- |
| 初始 | 未读 | 发送消息 |
| 未读 | 已读 | 打开或标记已读 |
| 未读 | 已删除 | 删除 |
| 已读 | 已删除 | 删除 |

### 禁止转换

- 状态转换图中未定义的转换一律禁止。
- 前端不得直接指定目标状态，后端必须根据当前状态和业务条件执行转换。
- 后续业务过程不得覆盖历史审核或操作状态。

## 07 权限管理

### 页面权限

- 仅当前登录客户账号可访问。

### 操作权限

- 操作权限按当前账号状态、数据权限和业务前置条件判断；本页涉及：按标题、内容快速筛选、高级筛选、批量删除、打开消息详情、批量标记已读。

### 数据权限

- 仅允许访问当前 customer_id 名下的数据；前端筛选不能替代后端数据权限校验。

## 08 系统交互

### 内部系统交互

| 交互对象 | 交互内容 | 调用时机 | 成功处理 | 失败处理 |
| --- | --- | --- | --- | --- |
| 当前客户会话 | 页面初始化、关联查询或状态计算 | 页面初始化或关联数据变更后 | 返回最新数据并刷新相关区域 | 保留当前上下文并允许重试 |
| 站内信 | 页面初始化、关联查询或状态计算 | 页面初始化或关联数据变更后 | 返回最新数据并刷新相关区域 | 保留当前上下文并允许重试 |
| 查询服务 | 按标题、内容快速筛选，高级筛选后按接收时间、消息类型和阅读状态筛选。查询参数和分页条件应由正式接口统一接收。 | 查询、筛选或分页时 | 返回匹配数据和总数 | 保留查询条件并允许重试 |
| 批量删除 | 提交当前业务对象标识、操作字段、操作人和客户端请求标识；后端重新校验业务前置条件。 | 用户确认提交时 | 返回最新状态并刷新关联数据 | 不写入成功状态，返回明确原因 |

> 当前原型使用浏览器 localStorage 模拟数据存取；正式接口路径、请求方法、错误码和超时阈值由前后端联调时确认。

## 09 异常与边界

### 重复操作

- 写操作必须携带客户端请求标识并保证幂等；重复提交不得重复创建记录、扣减数量或发送通知。

### 并发处理

- 后端在提交时重新校验记录版本、当前状态及数量；发生冲突时拒绝本次操作并返回最新数据。

### 超时处理

- 请求超时时保留当前查询或表单上下文，不得预先写入成功状态；重试时沿用原幂等标识。

### 数据异常

- 查询成功但无记录时展示明确空状态，保留可用的新增、返回或重试入口。
- 未登录、账号禁用、越权访问或数据不属于当前主体时终止操作，并返回无权限或安全的空结果。

## 11 通知信生成与内容格式规则

### 生成原则

- 站内信属于业务结果通知，只能由后端在业务状态成功变更后自动生成。
- 客户端只展示当前客户可见的业务结果类站内信。
- 产品审核申请、产品撤回申请、绑定申请等内部提交类动态不在客户端站内信中展示。
- 前端不得提供“新建站内信”“编辑站内信正文”“手动补发站内信”入口。
- 状态变更操作失败、接口超时或被后端回滚时，不得提前生成站内信。
- 重复点击、重复请求或页面刷新不得重复生成通知；后端需按 `source_type + source_id + target_status + receiver_customer_id` 做幂等控制。

### 自动触发场景

| 触发来源 | 状态变更 | 生成消息类型 | 接收方 | 是否生成 |
| --- | --- | --- | --- | --- |
| 绑定审核 / 已有产品追加绑定 | 待审批 → 已通过 | 绑定审核结果 | 当前客户 | 是 |
| 绑定审核 / 已有产品追加绑定 | 待审批 → 已驳回 | 绑定审核结果 | 当前客户 | 是 |
| 绑定审核 / 新建产品并绑定 | 待审核 → 已激活 | 绑定审核结果 | 当前客户 | 是 |
| 绑定审核 / 新建产品并绑定 | 待审核 → 已驳回 | 绑定审核结果 | 当前客户 | 是 |
| 运营端直接绑定产品 | 订单码段绑定成功并生成激活记录 | 绑定审核结果 | 当前客户 | 是 |
| 撤回审核 | 待审批 → 已通过 | 撤回审核结果 | 当前客户 | 是 |
| 撤回审核 | 待审批 → 已驳回 | 撤回审核结果 | 当前客户 | 是 |
| 码段生成、码段分配、保存草稿、提交申请、查询筛选、阅读消息、删除消息 | 非结果状态变更 | — | — | 否 |

### 消息数据字段

| 字段 | 生成规则 |
| --- | --- |
| 消息类型 | 固定枚举：`绑定审核结果`、`撤回审核结果` |
| 消息标题 | 由业务对象、批次和处理结果拼接，控制在列表中可快速识别 |
| 内容摘要 | 由订单号、数量、码段、处理说明或驳回原因等关键字段组成 |
| 接收时间 | 业务状态成功变更的服务端时间 |
| 阅读状态 | 初始为未读；客户打开或标记已读后变更为已读 |
| 业务关联 | 至少记录来源类型、来源记录 ID、产品 ID、客户 ID；绑定类应记录订单号，撤回类应记录撤回申请记录 ID |

### 标题与摘要模板

| 场景 | 标题模板 | 内容摘要模板 |
| --- | --- | --- |
| 绑定审核通过 | `{产品名称}（批次：{产品批次}）绑定审核已通过` | `订单号：{订单号}；绑定数量：{绑定数量} 枚；绑定码段：{绑定码段}。` |
| 绑定审核驳回 | `{产品名称}（批次：{产品批次}）绑定审核已驳回` | `订单号：{订单号}；申请数量：{申请数量} 枚；申请码段：{申请码段}；驳回原因：{驳回原因}。` |
| 运营端直接绑定 | `{产品名称}（批次：{产品批次}）已由运营端绑定` | `订单号：{订单号}；绑定数量：{绑定数量} 枚；绑定码段：{绑定码段}。` |
| 码段撤回审核通过 | `{产品名称}（批次：{产品批次}）码段撤回审核已通过` | `撤回数量：{撤回数量} 枚；撤回码段：{撤回码段}；处理说明：所选码段已重置。` |
| 产品撤回审核通过 | `{产品名称}（批次：{产品批次}）产品撤回审核已通过` | `撤回数量：{撤回数量} 枚；撤回码段：{撤回码段}；处理说明：产品关联码段已重置。` |
| 撤回审核驳回 | `{产品名称}（批次：{产品批次}）{码段撤回/产品撤回}审核已驳回` | `申请数量：{申请数量} 枚；申请码段：{申请码段}；驳回原因：{驳回原因}。` |

### 详情正文格式

```text
{客户名称}，您好：

{消息标题}。{内容摘要}

溯源质控码平台
```

### 结构规则

- 标题只保留业务对象和结果摘要，不拼接过多数值字段，避免影响列表扫描。
- 内容摘要必须保留关键业务字段，且与详情正文中的字段完全一致。
- 正文必须保留客户称呼、业务对象、处理结果、关键数量、码段范围和平台署名。
- `{产品批次}` 有值时显示为 `（批次：{产品批次}）`，为空时整段批次括号不显示。
- `{数量}` 使用千分位数字并追加单位“枚”，例如 `1,000 枚`。
- `{码段}` 使用连续码段范围；多段码段用 `、` 分隔。
- 通过类通知必须包含处理结果和已生效的码段/数量。
- 驳回类通知必须包含驳回原因；原因为空时使用默认文案“请根据审核意见修改后重新提交”或“请根据审核意见处理”。
- 当字段为空时，优先省略该字段，不在正文中写空字符串、`null`、`undefined` 或无意义占位。

### 状态流转图

```mermaid
flowchart TD
  start["业务操作提交"] --> validate["后端校验权限、状态和数据归属"]
  validate -->|失败| noMessage["返回失败，不生成站内信"]
  validate -->|成功| updateStatus["写入业务目标状态"]
  updateStatus --> decide{"是否属于结果通知场景"}
  decide -->|否| endNoMessage["结束，不生成站内信"]
  decide -->|是| idempotent["按来源类型、来源 ID、目标状态、接收客户做幂等检查"]
  idempotent -->|已存在| endExisting["结束，保留既有站内信"]
  idempotent -->|不存在| create["生成站内信，初始未读"]
  create --> visible["客户端站内信列表展示"]
```
