    D["运营端下载完整包或部分样例"]

## 3. 码段生成与下载流程

```mermaid
sequenceDiagram
    actor O as 运营人员
    participant API as 平台服务
    participant Q as 异步任务
    participant S as 对象存储

    O->>API: 提交生成数量、宽度、高度、备注
    API->>API: 校验数量 1 至 10,000,000、尺寸 8 至 300 mm
    API->>API: 分配不重复的连续序列号范围
    API->>Q: 创建二维码生成任务
    API-->>O: 返回库存批次与任务状态
    Q->>S: 分批生成 SVG、manifest.csv、README.txt 并打包
    Q->>API: 回写文件地址、大小、校验值和完成状态
    O->>API: 请求部分样例或完整压缩包
    API-->>O: 返回下载地址或任务进度
```

正式系统中，大批量任务不得在单次 HTTP 请求或浏览器内同步生成。

## 4. 码段分配与撤销分配

```mermaid
sequenceDiagram
    actor O as 运营人员
    participant API as 平台服务
    participant B as 库存批次
    participant A as 分配订单

    O->>API: 选择启用客户、库存空闲区间、数量和备注
    API->>B: 锁定库存批次并重新计算空闲区间
    API->>API: 校验数量为正整数且不超过所选连续区间
    API->>A: 创建分配订单
    API->>B: 该区间计入已分配范围
    API-->>O: 返回订单详情

    alt 订单已激活为 0 且绑定申请中为 0
        O->>API: 填写原因并撤销分配
        API->>A: 状态改为已撤销并写入审计信息
        API->>B: 码段恢复为空闲库存
        API->>API: 取消关联草稿或待处理绑定流程
    else 已有激活或待审批申请
        API-->>O: 拒绝撤销并返回阻断原因
    end
```

撤销分配针对的是“客户码段归属填错”；产品撤回针对的是“已经绑定产品的码需要重置”。二者不得混用。

## 5. 客户绑定流程

### 5.1 已有产品追加绑定

```mermaid
flowchart TD
    A["客户进入本人有效订单"] --> B{"剩余可用码量是否大于 0"}
    B -->|"否"| C["不显示绑定入口"]
    B -->|"是"| D["选择本人已激活产品"]
    D --> E["输入绑定数量"]
    E --> F["系统从空闲区间计算连续申请码段"]
    F --> G{"同一订单和产品是否已有待审批申请"}
    G -->|"是"| H["阻止重复提交"]
    G -->|"否"| I["生成绑定申请并预占码段"]
```

### 5.2 新建产品并绑定

```mermaid
flowchart TD
    A["客户从本人有效订单发起"] --> B["填写产品信息"]
    B --> C["填写企业信息"]
    C --> D["填写生产单位"]
    D --> E["填写质量信息"]
    E --> F["填写生产追溯"]
    F --> G["设置申请数量与连续码段"]
    G --> H{"保存还是提交"}
    H -->|"保存"| I["产品草稿，不占用审批状态"]
    H -->|"提交"| J["产品待审核，同时形成组合绑定申请"]
    J --> K["运营端一次审核产品资料和绑定信息"]
```

## 6. 绑定审核与激活

```mermaid
sequenceDiagram
    actor O as 运营审核人员
    participant R as 绑定申请
    participant A as 分配订单
    participant P as 产品
    participant N as 通知

    O->>R: 打开待审批记录
    O->>A: 核对客户、订单、数量和连续码段
    O->>P: 核对五模块产品资料
    alt 审核驳回
        O->>R: 写入驳回原因与处理人
        R->>A: 释放待审批码段占用
        R->>N: 通知客户修改后重提
    else 审核通过
        O->>A: 建立有效激活记录
        O->>P: 产品状态设为已激活并累计有效码量
        O->>R: 状态设为已通过
        O->>N: 通知客户已绑定并激活
    end
```

运营端还可以从订单详情选择该客户名下的已激活产品直接绑定。直接绑定不产生待审批申请，但必须执行相同的码段可用性校验并建立激活记录。

## 7. 产品撤回流程

```mermaid
sequenceDiagram
    actor C as 客户
    participant API as 平台服务
    participant W as 撤回申请
    participant A as 激活记录
    actor O as 运营审核人员

    C->>API: 选择产品及具体有效激活码段，填写原因
    API->>API: 排除已重置和已有待审批撤回的码段
    API->>W: 创建待审批撤回申请
    O->>W: 核对订单、码段、数量和原因
    alt 驳回
        O->>W: 写入驳回原因
        API-->>C: 通知驳回，激活关系保持有效
    else 通过
        O->>A: 将申请范围对应的激活记录全部或部分重置
        API->>API: 回滚订单、客户和产品有效码量
        API->>W: 写入实际回滚数量和重置范围
        API-->>C: 通知撤回通过
    end
```

## 8. 扫码状态解析流程

```mermaid
flowchart TD
    A["输入单个序列号"] --> B{"是否为预览码"}
    B -->|"是"| C["展示当前草稿预览，不计扫码次数"]
    B -->|"否"| D{"是否存在比最近重置更晚的有效激活记录"}
    D -->|"是"| E["已激活：展示固定横幅和公开产品资料"]
    D -->|"否"| F{"是否存在已通过撤回产生的重置记录"}
    F -->|"是"| G["已重置：展示空白状态说明"]
    F -->|"否"| H["未激活：展示未关联产品说明"]
    E --> I["服务端记录该序列号查询次数和时间"]
```

新激活时间晚于旧重置时间时，码可以重新进入已激活状态。
