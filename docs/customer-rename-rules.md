# 客户改名与历史一致性

## 适用范围

确认日期：2026-11-02。适用于运营端、客户端和扫码端。本文是用户确认的目标规则。本次仅更新标注和需求说明，业务实现仍有差异，见下文。

## 基本规则

- 客户 ID 是固定身份。客户名称是可修改的展示信息，不能用名称判断业务归属。共享公司号下的不同客户仍按各自 ID 区分。
- 日常列表、客户选择、客户名称搜索、统计和查码归属使用当前名称。新名称应能查到改名前后的相关业务，仍受原有权限和状态筛选限制。
- 订单创建时保存客户名称快照。两端订单详情使用创建时快照；台账和日常查询使用当前名称。新订单保存新名称，已有快照不覆盖。
- 已发布产品的企业名称、图文、图片和附件不因客户改名自动变化。扫码端继续读取产品公开资料。资料确需变化时，走原有产品资料编辑流程。
- 从订单新建产品时，“公司名称”默认带入该订单内的客户名称，资料可编辑时允许修改。修改只保存在本产品企业资料中，不回写客户账号、订单客户名称或其他产品，也不改变订单归属和绑定关系。已有草稿保留用户填写的值。
- 每次改名记录前后名称、操作人和时间。修改记录说明发生了什么变化；快照保留业务发生时的信息，两者分别维护。

## 数据处理口径

| 数据或入口 | 目标规则 |
| --- | --- |
| 客户列表、客户详情和客户选择 | 显示当前名称；客户 ID、登录账号、公司号及类型不因改名变化。 |
| 创建订单草稿 | 保留客户 ID，再次展示或提交时读取当前名称，正式创建时保存名称快照。 |
| 两端订单台账和客户订单记录 | 按客户 ID 关联；客户名称展示、搜索及日常台账导出使用当前名称。 |
| 两端订单详情 | 客户名称使用创建时快照；后续绑定及权限校验按客户 ID。 |
| 未绑定、部分绑定、全部绑定订单 | 改名不改变状态、码量、待审批占用、绑定关系和操作资格。 |
| 已撤销订单 | 保留快照和撤销记录；改名不恢复订单，不释放或重分配号码。 |
| 产品草稿、待审核、已驳回和已发布产品 | 所属客户显示当前名称。产品资料中的企业名称独立保存，不能随所属客户名称批量替换。 |
| 绑定、撤回申请及记录 | 所属客户显示当前名称；保留申请内容、审核结果、意见、时间和操作人。改名不触发审批或重提。 |
| 已有产品追加绑定 | 按客户 ID 及原有品类规则校验；新旧名称不同不能阻断同一客户，同名不能放行其他客户。 |
| 统计、下级明细及关联订单 | 按客户 ID 聚合，以当前名称显示和搜索；改名不拆组，不合并其他客户，不改变码量及排序依据。 |
| 运营查码 | 归属客户显示当前名称；码号、订单、序号、绑定状态及扫码记录不变。 |
| 扫码端 | 继续显示关联产品的公开企业资料，不用客户账号名称覆盖，不公开账号修改记录。 |
| 站内信 | 收件权限按客户 ID，所属客户显示当前名称；已发标题、正文、发送时间及历史操作人不批量改写。 |
| 导出及已下载文件 | 新导出的日常列表、台账和统计使用当前名称，订单快照字段保留原值；已下载文件不追溯修改。 |

改名用于同一客户的名称维护。业务主体变成另一家公司时，应另建客户账号，不能通过改名转移订单。本次不新增主体识别或改名审批功能。

## 当前实现差异

核对依据：`js/core/customer-management.js`、`js/core/domain.js`、`js/core/order-management.js`、`js/core/order-statistics.js` 和 `js/core/code-query.js`。

- 当前主要业务已通过客户 ID 关联，保存修改记录并保留订单客户快照。查码归属优先读取当前名称。
- 订单台账展示、客户名称搜索及统计标签仍有直接读取订单旧名称的路径，尚未统一为当前名称。
- 改名会更新产品所属客户、绑定申请、撤回申请及消息的客户字段，不会统一重写产品企业资料或已有消息正文。后续应区分动态展示字段与历史内容字段。
- 从订单新建产品时，按订单内客户名称预填公司名称，用户可修改并独立保存。订单客户名称与客户当前名称不同时，仍按订单内名称预填，不自动覆盖已有产品资料。
- 缺少客户 ID 的历史记录，只能在旧名称能唯一对应客户时补齐身份；无法唯一确定时需人工核对，不能按共享公司号或同名自动合并。
- 缺少名称快照的旧订单，只能用现存订单名称补录并说明来源；不能将当前名称冒充创建时名称。

以上差异待后续业务开发处理。本次文档更新不代表实现已完成或业务验收已通过。
